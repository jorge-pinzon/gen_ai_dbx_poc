Read the verdict correctly

Reliability = workflows successful within target ÷ all measured workflows. Late answers miss the target. A completed experiment can fail its reliability requirement.

¹ Failures include FAILED, DEADLINE_EXCEEDED and INTERRUPTED. Percentiles use nearest rank and include successful-but-late answers. The 1-client baseline has a small sample; one passing run does not establish long-term reliability.

Scope and attribution

This tests POST /api/v1/chat through the selected Flask deployment. Timings include network/proxy delays, Flask scheduling, backend work, citations, persistence and analytics. Internal Databricks invocations are not observed by this client.

Workers issue requests continuously without employee think time. Local debug-server results describe that setup; deployed-server capacity must be tested separately. Missing HTTP responses or generic exception chains require additional server-side investigation.
