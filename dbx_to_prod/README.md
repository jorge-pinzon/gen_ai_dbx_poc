# dbx_to_prod

Kit for moving the Mariner GenAI system from the trial Databricks account to the prod account.

Open **[index.html](index.html)** for the full guide. In short, run these in order:

1. `notebooks/00_config.py`: edit the first cell (app service principal, warehouse name, `COACHING360`).
2. `notebooks/01_setup_unity_catalog.py` (prod)
3. `notebooks/02_migrate_data.py` mode `export` (trial) → `scripts/copy_between_workspaces.sh` → mode `import` (prod)
4. `notebooks/02b_coaching360_views.py` (prod; skip when `COACHING360 = False`)
5. `notebooks/03_ingest_documents.py` → `04_vector_search.py` → `05_custom_agents.py` → `06_agent_bricks.py` (prod)
6. Deploy the app with `app/app.yaml` and `app/env.prod.template`, then run `notebooks/07_validate.py`.

Names match the trial workspace (`workspace.default`, `workspace.performance_test`,
`workspace.coaching360demo`, `workspace.c360_*`). If prod uses another catalog, run
`scripts/retarget.py` first. `exports/` holds the raw read-only trial exports (no secrets, no data
rows), taken on 2026-10-23 before Coaching360 was added.

Coaching360 files are copies: `sql/coaching360` from `coaching360/sql` (generated by
`coaching360/build_sql.py`) and `agents/agent_bricks/coaching360` from `coaching360/agents`
(generated by `coaching360/build_agents.py`). After regenerating there, copy them again.
`COACHING360_ENABLED` ships `false` in the app settings: the chat's persona model is demo-only
(guide, section 11).
